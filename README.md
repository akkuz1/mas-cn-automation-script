mas-cn 是 Windows 与 Office 激活工具 MAS 的中文汉化版，在不改动机器码的前提下按所选激活方式提供永久激活。脚本内置 HWID、Ohook、TSforge、KMS38 与在线 KMS 等多种激活方式，并附带高级故障排除功能。汉化流程先由脚本自动初翻、再经人工校对，同时处理了中文显示兼容与远程执行细节。使用前建议暂时关闭 Defender 实时扫描，以免脚本被误判删除。修改或分发代码请遵循 GPL-3.0，并注明来源或提供获取源代码的途径。

## 功能简介

`mas-cn` 是 Microsoft-Activation-Scripts 的中文本地化版本，面向 Windows 与 Office 的激活场景，保留原版全部激活逻辑，仅对界面提示、错误信息和交互流程做汉化处理，脚本行为与英文原版一致。

核心能力：

- **多种激活方式并存**：支持 HWID、Ohook、TSforge、KMS38 以及在线 KMS，可根据系统版本与 Office 产品类型选择对应方案，无需在多个工具之间切换。
- **中文交互界面**：菜单、状态提示、失败原因均以中文呈现，降低对照英文文档排查的成本；同时处理了中文编码兼容问题，避免控制台出现乱码。
- **离线与在线两条路径**：部分激活方式完全离线执行，部分依赖在线 KMS 服务，脚本会在选择时标注差异，便于按网络环境取舍。
- **自动化故障排查**：内置对激活状态的检测与常见问题修复流程，可在激活失败后直接运行排查项，而不必手动逐条核对系统状态。
- **脚本化调用**：支持通过 PowerShell 直接拉取并执行，也提供可双击运行的 cmd 入口，适合批量部署或封装进自有运维流程。
- **可持续同步上游**：汉化基于脚本化流程生成初稿再人工校对，随上游版本迭代同步更新，变更范围以报告形式记录，便于核对差异。

使用前需注意：Windows Defender 存在误报并删除脚本的概率，执行前应关闭实时扫描或将工作目录加入排除项；脚本不修改系统镜像，激活结果依赖所选方式，具体持久性差异见后文激活方式对比。

- 首次运行前请暂时关闭 Windows Defender 实时扫描，该工具为脚本型激活器，存在被误判删除的概率；如文件已被隔离，请先从隔离区恢复并添加排除项。
- 执行前确认当前 PowerShell 会话具备管理员权限，否则激活相关操作会因权限不足而中断。
- 若提示执行策略受限，可在当前会话中临时放宽策略后重试，避免修改系统全局设置。

### 方式二：本地脚本文件

从本仓库的 Release 页面获取最新的命令脚本文件，直接双击或右键以管理员身份运行。该方式不依赖网络拉取，适合离线环境或内联调用被拦截的场景。

- 下载后请核对文件完整性，避免使用来源不明的副本。
- 运行过程中按提示选择激活项即可，脚本会在终端内输出每一步的执行结果。
- 若终端一闪而过，请改用「以管理员身份运行」或在已打开的终端中手动调用该文件，以便查看完整日志。

### 运行前检查清单

- 系统已联网（在线 KMS 与部分校验环节需要网络）。
- 已关闭第三方安全软件的脚本拦截，或将本工具加入白名单。
- 当前账户为管理员账户，UAC 提示已确认。

1. 启动脚本，进入中文主菜单。
2. 根据目标产品（Windows 或 Office）与期望的激活特性选择对应条目，各方式差异见「激活方式对比」一节。

4. 激活完成后按提示退出，必要时重启相关服务或系统使状态生效。

## 配置说明

**运行方式**

脚本不写注册表、不装服务、不在系统盘留常驻文件，激活完成后即可关闭窗口。所有配置项都通过运行时参数或交互菜单传入，修改后仅对本次运行生效，无需清理残留。

**执行环境**

- PowerShell 5.1 及以上（Windows 10 / 11 自带），Windows 7 需改用兼容的下载执行方式。
- 建议以管理员权限运行，普通权限下部分涉及系统组件与授权的步骤会失败。
- 运行前暂时关闭实时防护，脚本的反射加载方式容易被误判为可疑行为。

**脚本级参数**

中文版新增的启动脚本支持以下可调项，按需在命令后追加：

- 语言选项：默认锁定简体中文界面，需要对照原版输出时可切换回英文提示。
- 静默/交互模式：交互模式逐步确认每一步操作，静默模式适用于批量或无人值守场景，但会跳过人工核对环节。
- 日志输出：开启后将激活过程写入本地日志文件，便于失败时回查具体步骤；日志仅记录操作流程，不包含密钥明文。
- 自动退出：脚本执行完毕后自动关闭窗口，避免停留在等待输入的状态。

**激活方式的选择**

菜单中的 HWID、Ohook、TSforge、KMS38、在线 KMS 对应不同的持久化机制与适用系统版本。选择前先确认目标系统与 Office 版本：HWID 仅适用于 Windows 10 / 11，Ohook 面向 Office，KMS 系列需要考虑续期周期。配置项之间不叠加，同一台机器重复运行不同方式时，后一次会覆盖前一次的授权状态。

**Office 相关配置**

Ohook 方式需指定 Office 的安装路径与版本通道；若本机存在多个 Office 版本或残留许可证，脚本会提示清理旧授权，按提示确认即可。激活前建议先关闭所有 Office 进程，否则部分文件被占用会导致写入失败。

**KMS 相关参数**

在线 KMS 与 KMS38 涉及服务器地址与端口，脚本内置默认值，一般无需改动。若处于受限网络环境，可改为本地或内网 KMS 地址；端口需与服务器配置一致，否则会返回连接超时。KMS 激活有周期限制，到期前需重新运行以续期。

**故障排查开关**

脚本内置高级排错选项，可单独执行授权状态查询、清理残留许可证、重置激活计数等操作。遇到激活失败时，先运行状态查询确认当前授权类型与剩余期限，再决定是清理重试还是更换激活方式。排错操作具有破坏性，执行前确认无需保留现有授权信息。

## 激活方式对比

mas-cn 把多种激活方式集中在一个脚本菜单里，选哪种取决于你的硬件环境、系统版本和是否需要重装后自动恢复。下面按实际使用场景做个横向对比，方便你按需选择。

### 方式一览

| 方式 | 适用对象 | 激活性质 | 联网要求 |
| --- | --- | --- | --- |
| HWID | Windows 10 / 11 | 永久（数字许可证） | 需联网一次 |
| Ohook | Office | 永久（本地挂钩） | 无需联网 |
| TSforge | Windows / Office | 永久（写入激活存储） | 无需联网 |
| KMS38 | Windows 10 / 11 / Server | 至 2038 年 | 需联网一次 |
| 在线 KMS | Windows / Office | 180 天循环 | 需定期联网 |

### 关键维度对比

**离线可用性**
HWID、KMS38 和在线 KMS 在首次激活时都需要连接服务器；Ohook 与 TSforge 全程离线即可完成，适合无网络或网络受限的机器。

**持久性**
HWID 绑定硬件，同一台机器重装系统后通常可自动恢复；Ohook 把激活信息落在本地，重装 Office 后需重新执行；TSforge 写入系统激活存储，重装后一般需要重跑脚本；KMS38 激活有效期到 2038 年；在线 KMS 每 180 天需续期一次。

**对系统的影响**
Ohook 不修改系统激活状态文件，卸载 Office 后残留较少；TSforge 会在激活存储中留下记录；HWID 依赖微软服务器下发的数字许可证，本机几乎不落文件。

**硬件变更后的表现**
HWID 更换主板等核心硬件后可能失效；Ohook 与 TSforge 对硬件变动不敏感；KMS38 在硬件大改后需重新处理。

**Windows 版本升级**
HWID 和 Ohook 在 Windows 10 与 11 之间功能升级后通常仍有效；TSforge 与 KMS38 在跨大版本升级后建议复查一次激活状态。

### 选择建议

- 家用 Windows 10 / 11，追求一次搞定、重装可恢复：优先 HWID。
- 只想激活 Office，且不希望改动系统激活状态：选 Ohook。
- 完全离线环境，或希望 Windows 与 Office 一次性处理：选 TSforge。
- 需要长期稳定、不想频繁续期，且能接受联网一次：选 KMS38。
- 临时或测试环境，能接受定期续期：用在线 KMS。

脚本启动后会在菜单中列出全部选项，每种方式执行前都有中文说明，照着提示走即可。若某一种方式在你的环境里失败，换另一种通常就能解决——这也是 mas-cn 把多种方式打包在一起的意义。

## 常见问题

**激活失败怎么办？**

先看脚本给出的错误码，对照常见原因排查：

- 提示需要联网的激活方式（在线 KMS、HWID 首次激活）失败：检查网络与 DNS，必要时换网络重试。
- 提示权限不足：务必以管理员身份运行 PowerShell 或终端，再执行脚本。
- 激活后系统仍显示未激活：重启一次，或在系统设置里手动触发一次激活检查后再看状态。

**脚本一闪而过 / 没反应？**

多为执行策略或下载被拦截导致。确认当前窗口有管理员权限，并检查安全软件是否拦截了脚本的下载与执行。若通过命令方式始终无法运行，可改用仓库 Release 中提供的 cmd 文件直接打开使用。

**Windows Defender 报毒 / 文件被删？**

这是脚本类工具常见的误报。使用前临时关闭实时扫描，完成激活后再重新开启。不要从非本仓库渠道获取脚本文件。

**激活后能维持多久？**

取决于所选激活方式：部分方式为永久激活，部分为周期性续期（约 180 天一次），还有的仅在当前硬件或当前系统版本内有效。切换激活方式前先确认其特性，避免误以为“永久”而实际需要定期维护。

**换了硬件或重装系统后还要重新激活吗？**

视方式而定。有的方式绑定硬件，更换主板等主要部件后会失效；有的方式在系统功能升级后仍保留。重装前记录当前使用的激活方式，重装后按相同方式重新执行即可。

**Office 和 Windows 可以分开激活吗？**

可以。脚本按目标分别处理，Windows 与 Office 互不影响。只激活其中一项时，选择对应菜单项操作即可。

**汉化版和原版有什么区别？**

本仓库仅做中文汉化与显示兼容处理，激活逻辑与原版一致。遇到汉化相关的显示问题可反馈；涉及激活机制本身的问题，请以原版说明为准。

**需要卸载残留或还原系统吗？**

多数方式不会在系统中长期驻留文件，无需额外清理。若曾使用会写入计划任务或服务的方式，切换前先在该方式的菜单中执行对应的移除/还原操作，再换用其他方式。

**在虚拟机或精简系统上能用吗？**

可以尝试，但精简系统可能缺少激活相关组件，虚拟机还需保证网络与硬件标识稳定。失败时优先换用不依赖联网的方式测试，以判断是环境问题还是网络问题。

**执行脚本会不会改动机器码或系统文件？**

是否改动取决于所选激活方式；部分方式会写入系统以维持激活状态，部分方式不改动机器码。使用前阅读各方式说明，按需选择，不要在未确认的情况下批量套用到生产环境。
